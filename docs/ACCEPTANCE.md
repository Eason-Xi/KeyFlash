# 接入真实服务后的验收

以下步骤尚未在真实 Supabase 或硬件上执行。请使用专门的测试项目和可恢复的开发板。

## 账号与发布

1. 应用迁移、配置环境变量和邮箱回调；重启应用，确认示例项目消失。
2. 注册 A、验证邮箱、登录。确认公开 profiles 没有 email 字段。
3. 在工作台创建项目，填写真实芯片、PCB 版本、引脚要求和仓库地址。
4. 上传已知可工作的 BIN 文件。按实际 flash_args 填写地址，发布 1.0.0。
5. 确认项目卡片版本与更新时间更新；访客能看到版本并下载，SHA-256 与本地一致。
6. 尝试重复版本、重叠地址、超大文件、非 BIN、别人的上传路径，确认被拒绝。
7. 编辑简介后返回工作台，确认保存结果；已有版本的项目不能更改芯片。
8. 发起重置密码，打开邮件链接，设置新密码并重新登录。
9. 退出后打开某项目的在线烧录页，点击“登录账号”，登录后应回到该烧录页。
10. 用与已有用户仅大小写不同的昵称注册，确认昵称被追加后缀、作者主页各自独立。
11. 重复项目标识、重复版本号、错误密码均显示中文提示，而不是数据库或 Auth 的英文原文。
12. 退出后选择“用验证码登录”，输入 A 的邮箱，确认收到的邮件是 6 位验证码（不是链接）；输错一次显示中文提示，输对后登录成功。用未注册邮箱获取验证码，应提示先注册，且不会新建账号。
13. 启用 GitHub Provider 后，从某项目的烧录页进入登录，点击“使用 GitHub 登录”，授权后应直接回到该烧录页；新账号的公开昵称为 GitHub 用户名。在 GitHub 授权页点“取消”，回到登录页应显示中文错误。

## 隔离与社区

1. A 收藏并评价项目，提交兼容性记录。
2. 注册 B；B 看得到公开评论与兼容性，但看不到 A 的收藏和烧录记录。
3. B 无法修改 A 的项目、关闭 A 的版本烧录，无法覆盖/删除 A 的文件。
4. A 更新评分后，项目评分只按 A 一个用户计算。
5. A 发布新版本，旧版仍可下载，关闭旧版在线烧录后无法开始旧版会话。

## 实体硬件

逐项在 ESP32、ESP32-S3、ESP32-C3 及目标 PCB 上验证：

1. Chrome / Edge 在 HTTPS 或 localhost 打开。使用有数据能力的 USB 线。
2. 取消串口选择，检查页面可重试。
3. 用不匹配芯片连接项目，确认在擦写前拒绝并释放串口。
4. 用地址范围超过设备 Flash 的版本验证容量保护。
5. 替换测试下载响应中的字节，验证 SHA-256 失败时不会开始写入。
6. 正常烧录，核对日志、进度、设备 MD5、重启、USB 枚举、按键和旋钮。
7. 分别验证仅目标扇区擦除与全 Flash 擦除；核对配置保留/清除符合预期。
8. 写入中拔出设备，确认错误和失败记录；重新进入下载模式后可恢复。
9. 验证完成写入但无法自动重启时提示手动重启；网络中断导致历史不同步时有日志。
10. 提交兼容性结果，确认版本、硬件、系统、浏览器和外设状态准确。

## 上线前

配置生产 SMTP、HTTPS、Auth 回调、备份、Supabase Storage 容量预算及 Auth 限流。执行 Supabase 数据库 advisors 检查部署环境。生产仍需对来自社区的固件进行来源审核；本 MVP 没有管理员审核/举报工作流。
